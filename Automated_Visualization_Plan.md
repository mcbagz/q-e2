# Task: Automated Post-Processing Visualization in pp.x

## 1. Vision & Goal

The primary goal of this task is to simplify and automate the post-processing of Quantum ESPRESSO calculations. Currently, generating visualizations requires a user to manually create specific input files for the `pp.x` executable, which can be non-intuitive.

This feature will introduce a new, user-friendly workflow. By using a single new command-line flag (`--visualize-all`), a user will be able to point the `pp.x` tool at a completed calculation's output directory. The tool will then intelligently analyze the results and automatically generate every possible visualization the data allows for, such as charge densities, wavefunctions, potentials, and more.

This will make the process of visualizing results significantly faster, easier, and more comprehensive for both new and experienced users.

## 2. Architectural Alignment

This work is centered entirely within the **`PP` (Post-Processing)** module, specifically modifying the `pp.x` executable. This aligns perfectly with the project's architecture, which designates `PP` as the primary tool for analyzing and visualizing data generated by computational engines like `PW`. The new functionality will be implemented as a separate code path, ensuring that the existing, namelist-driven workflow of `pp.x` remains untouched and functional, which adheres to best practices for extending a large, established codebase.

## 3. Main Task Breakdown

### Subtask 3.1: Add Command-Line Flag Parsing to `pp.x`

*   **Title:** Add `--visualize-all` Flag and Argument Parsing
*   **Description:** Modify the main program of `pp.x` to handle command-line arguments. This is a prerequisite for the new automated mode.
*   **Implementation Details:**
    1.  **File to Modify:** `PP/src/postproc.f90`.
    2.  In the `PROGRAM pp` block, use the `get_command_line_argument` intrinsic to check for the presence of a `--visualize-all` flag.
    3.  The parser should also expect a path to the calculation's output directory (e.g., `pp.x --visualize-all -in out/si.save`).
    4.  Introduce a new logical variable, e.g., `visualize_all_mode`, which is set to `.TRUE.` if the flag is detected.
    5.  Wrap the existing program logic (which reads from standard input) in an `IF (.NOT. visualize_all_mode) THEN ... END IF` block to ensure backward compatibility.

### Subtask 3.2: Implement Calculation Data Analysis

*   **Title:** Create Data Analysis Module
*   **Description:** Develop a new module that can inspect a completed calculation's output directory and determine what data is available for plotting.
*   **Implementation Details:**
    1.  **New Module:** Create a new file, e.g., `PP/src/auto_vis_analyzer.f90`, containing a module `auto_vis_analyzer_mod`.
    2.  **Core Subroutine:** Implement a subroutine, e.g., `analyze_output_directory(out_dir, available_plots)`, that takes the output directory path as input.
    3.  **XML Parsing:** This subroutine must parse the `data-file-schema.xml` file located in the `out_dir`. It needs to extract key information, such as:
        *   Was the calculation spin-polarized? (`nspin > 1`)
        *   Is charge density data available? (`<charge-density ...>`)
        *   Are wavefunctions saved? (`<eigenvalues ...>`)
        *   Is the local potential available? (`<local-potential ...>`)
    4.  **Output:** The subroutine should return a data structure (e.g., an array of logicals or a derived type) that flags which types of plots can be generated.

### Subtask 3.3: Develop Automated Plotting Logic

*   **Title:** Implement the `auto_visualize` Subroutine
*   **Description:** Create the main driver subroutine that orchestrates the automated visualization process.
*   **Implementation Details:**
    1.  **New Subroutine:** Create a new subroutine `auto_visualize(out_dir)` within the `pp_module` or a new dedicated module.
    2.  **Call Analyzer:** This subroutine will first call `analyze_output_directory` from Subtask 3.2 to get the list of available plots.
    3.  **Plotting Loop:** It will then iterate through the `available_plots` data. For each available plot type, it will:
        *   Programmatically set the required `inputpp` namelist variables (e.g., `plot_num`, `iflag`, `filplot`). For example, if charge density is available, it will set `plot_num = 0`.
        *   Call the appropriate underlying plotting routines from `pp.x` (like `punch_plot`) with the correct parameters.
        *   Generate a descriptive output filename (e.g., `charge_density.xsf`, `elf_slice_2d.dat`).
    4.  **Execution:** This subroutine will be called from the main `PROGRAM pp` block when `visualize_all_mode` is true.

### Subtask 3.4: Create a Summary Report

*   **Title:** Generate a User-Friendly Summary
*   **Description:** At the end of the automated process, provide the user with a clear summary of what was generated.
*   **Implementation Details:**
    1.  As the `auto_visualize` subroutine generates each plot, it should store the output filename and a brief description in an array.
    2.  After the plotting loop is complete, it will print a formatted table to the standard output, for example:
        ```
        Automated Visualization Complete. The following files were generated:
        --------------------------------------------------------------------
        File                       Description
        --------------------------------------------------------------------
        charge_density.xsf         Total charge density in XSF format
        elf.xsf                    Electron Localization Function (ELF)
        potential_slice_xy.dat     Local potential sliced on the XY plane
        ...
        --------------------------------------------------------------------
        ```

### Subtask 3.5: Write Documentation and Tests

*   **Title:** Document and Test the New Feature
*   **Description:** Ensure the new feature is well-documented and robustly tested.
*   **Implementation Details:**
    1.  **Documentation:**
        *   Update the `Doc/INPUT_PP.md` file to describe the new `--visualize-all` flag and its usage.
        *   Provide a clear example of how to use the new feature.
    2.  **Testing:**
        *   Create a new test in the `test-suite/` directory.
        *   The test should consist of a small, completed `pw.x` calculation.
        *   The test script will then run `pp.x --visualize-all` on the output of that calculation.
        *   The test will pass if the command executes successfully and a predefined set of output visualization files are created.
